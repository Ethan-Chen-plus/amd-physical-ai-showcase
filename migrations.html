03 / JAX RUNTIME

ROCm JAX / OpenPI：官方路线与真实边界

JAX 0.10.0 已验证

这条迁移线不是为了“把 JAX 改成 PyTorch”。Pi0/Pi0.5 的官方 OpenPI 实现本来就是 JAX/Flax，因此我们先按 AMD 官方路径验证原生 JAX，再把无法在当前硬件算子上稳定执行的分支单独记录。

  • 官方入口ROCm JAX 安装指南；对应 Docker 镜像为 rocm/jax:rocm7.14-jax0.10.0-py3.12
  • 已完成JAX GPU backend、官方 75k Pi0.5 checkpoint、tokenizer、归一化统计和 OpenPI 加载链路均已通过
  • 算子修复隔离 Gemma softmax 路径，避开 gfx1151 的 64 KiB shared-memory 限制；MuJoCo 视频使用 OSMesa 做无窗口渲染
  • 诊断证据真实 RoboCasa seed 9 完成 1/1 pretrain rollout；这是迁移诊断，不是正式成功率
  • 正式结果同一 16 任务 × 50 episodes 协议下，Pi0.5 为 142/800 = 17.75%；完整 JSON、视频和 SHA 已归档
0.10.0ROCm JAX1 / 1diagnostic rollout142 / 800formal Pi0.5 result

为什么仍有“JAX 转 PyTorch”的分支？

官方 RoboCasa365 路线已经用原生 JAX 跑通，不能和 DexJoCo 混为一谈。DexJoCo 当前旧 OpenPI 环境的 JAX 0.8.2 虽能识别 GPU，但 gfx1151 的 GEMM 触发 hipGetFuncBySymbol；因此我们准备了 CPU-JAX 导出到 SafeTensors、再用 AMD PyTorch 推理的兜底路线。它是兼容性桥接，不是对官方 JAX 结果的替代，也尚未产生策略成功率。
