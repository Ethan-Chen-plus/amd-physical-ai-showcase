01 / CONTEXT

从环境迁移到闭环

具身智能仓库同时依赖物理引擎、渲染后端、机器人资产、数据格式、训练框架和策略执行器。迁移的关键，是让这些接口在 AMD GPU 上保持同一套语义：模型读取正确的图像与状态，输出正确尺度的动作，模拟器按统一节奏执行并保存结果。

我们的迁移目标是一条可追踪、可复用的闭环：

环境与设备→场景与资产→专家数据→训练与 checkpoint→推理 bridge→固定评估
迁移的核心判断

环境与场景确认运行基础，数据与训练建立策略入口，推理与固定评估把策略接回物理世界。固定任务、seed、完整分母、视频、结果 JSON 和 SHA 共同组成可复核的闭环结果。

02 / ACCEPTANCE

六层验收：每一层都要有自己的证据

我们把迁移拆成六个层次，每一层都有明确的输入、验收项和修复动作。分层记录让环境、场景、数据、模型、推理和评估各自拥有清晰的工程边界。

01

环境

记录 ROCm、HIP、Python、PyTorch/JAX、模拟器和关键插件版本，并保存 GPU backend 证据。

02

仿真

官方场景完成 reset、step、render，在无窗口服务器上保存 MP4；渲染状态和物理状态分别记录。

03

数据

审计 observation/action 维度、时间顺序、episode 边界、终止 padding 和 normalization stats。

04

训练

官方入口能启动，日志可读，checkpoint 可校验，断点续训沿用同一 output_dir 与配置。

05

推理

推理使用与训练匹配的权重、tokenizer、stats、相机映射、action chunk 和执行节奏。

06

评估

固定任务、seed、进程拓扑和分母；每条结果绑定 JSON、视频和 SHA，并区分正式、诊断、展示。

03 / CASE STUDY

DISCOVERSE：从“能启动”到四个高清任务

DISCOVERSE 是我们迁移工作中最完整的一条线，覆盖 MuJoCo 任务、AIRBOT/MMK2 机器人、专家轨迹、ACT/DP/PPO/RDT 入口、无窗口渲染、MP4 输出，以及 ROS2、LiDAR、3DGS 等外围能力。我们将仿真、策略、传感器和渲染分别接入同一套 AMD 运行记录，形成可复用的迁移模板。

18 / 18核心运行链路
12 / 12AIRBOT 任务
8 / 8MMK2 任务
31 / 31block bridge 严格专家回放

3.1 专家轨迹与 IK 可达性

block_bridge_place 的官方 79 阶段专家路径暴露出 IK 可达性与支撑物碰撞的组合问题。我们保留原始路径用于定位，并将严格专家 suffix 回放链路独立验收，最终达到 31/31。这个案例沉淀出一套可复用方法：先检查末端可达空间，再检查支撑物碰撞，最后固定轨迹和任务定义。

3.2 无窗口渲染与视频输出

服务器没有桌面时，我们使用 MuJoCo offscreen、OSMesa 或平台对应的 headless 后端输出 RGB 帧，再编码为 MP4。渲染告警、画面分辨率、物理状态和成功谓词分别写入结果记录，使服务器端任务也能产生稳定、清晰的视觉档案。

3.3 高清多视角回放

我们为四个 MMK2 官方任务制作了三机位原生视频：box pick、drawer open、cabinet door open、coffee cup to plate。每个任务均为严格 1/1 成功，原生视频为 1920×1080；多视角同步呈现末端动作、物体状态和场景变化，成为 DISCOVERSE 的可视化成果档案。

3.4 Gaussian Splatting 运行时

DISCOVERSE 的基础 MuJoCo 环境和 3DGS/策略环境采用隔离运行时。基础环境服务于轻量仿真与控制，3DGS 使用 AMD ROCm-ML 环境；当前已验证 PyTorch 2.11.0+rocm7.13、HIP 7.13、Radeon 8060S 和 gaussian_renderer。启动脚本将渲染器绑定到对应运行时，保证点云、相机和动态回放使用同一套依赖。

# Select the ROCm-ML runtime for 3DGS renderer evaluation
source local_tools/activate_amd_runtime.sh
python -c "import torch, gaussian_renderer; print(torch.__version__, torch.version.hip, torch.cuda.is_available())"
python local_tools/verify_gaussian_renderer.py \\
  --robot rm2 --output results/gaussian/rm2.png \\
  --width 640 --height 360

RM2 和 SkyRover 的 3DGS renderer 已分别加载约 133 万和 102 万个高斯点，并输出 640×360 PNG。gfx1151 的 ROCm 构建使用项目本地适配版本；无桌面服务器则配置 headless OpenGL/OSMesa 路径，让渲染资产、相机运动和动态回放都能稳定输出。

05 / CASE STUDY

ROCm JAX 与 Pi0.5：让运行时进入策略闭环

AMD 官方已经提供 ROCm JAX 路线。真正的迁移工作是让 Python、ROCm、JAX、jaxlib、ROCm plugin、PJRT 和模型代码处于互相匹配的版本集合，并以整套版本组合推进升级。我们按 AMD 官方路线建立了隔离的 JAX 0.10.0 环境，GPU backend 识别为 rocm:0，gfx1151，64×64 矩阵计算通过。

从 JAX backend 到策略闭环

矩阵计算通过后，继续接入 checkpoint restore、tokenizer、normalization stats、视觉编码器、attention、相机输入、动作解码和环境闭环。页面将运行时指标、任务回放和多任务结果放在同一条证据链中。

5.1 旧环境的运行时症状

DexJoCo 旧环境使用 ROCm 7.2.1/JAX 0.8.2：GPU 可见，但 GEMM 触发 hipGetFuncBySymbol。另一条 Pi0.5 路线出现过 Gemma attention 的 64 KiB shared-memory 限制、MIOpen 卷积编译错误和 headless 视频依赖问题。它们分别对应目标 gfx kernel、显存布局、卷积编译和视频后端四类接口。

5.2 修复顺序

  1. 固定官方 AMD JAX 版本组合，完成 backend、矩阵、卷积和 attention 预检。
  2. 恢复 Orbax 参数、tokenizer 和归一化统计，适配参数树与 StepMetadata 的数据结构。
  3. 选择单个容易诊断的任务完成真实闭环，保存 MP4 和 action trace。
  4. 按官方多任务协议评估，并将单任务回放、多任务汇总与运行时指标统一归档。

07 / DEBUGGING

迁移中反复出现的九类工程要点

01 · GPU 身份

ROCm 的 PyTorch 设备接口

ROCm 复用 PyTorch 的 torch.cuda API。运行记录同时保存 torch.version.hip、rocminfo、GPU 型号和实际显存占用。

02 · Headless 渲染

离屏渲染与视频编码

Vulkan、CUDA denoiser 和无 DISPLAY 环境分别影响渲染路径。offscreen 图像、MP4 编码、物理状态和成功谓词拥有独立验收项。

03 · JAX 算子

目标 gfx 上的 kernel 组合

设备枚举之后，还要逐层验证 plugin、PJRT、MIOpen、attention 和特定 gfx kernel。固定版本组合是 AMD 运行时稳定性的基础。

04 · Action chunk

连续动作的执行契约

chunk 长度、重叠执行、temporal ensemble、absolute/relative qpos、夹爪编码和控制频率共同决定动作落地方式。

05 · Normalization

模型输入输出的统计契约

训练时的 stats、相机尺寸、颜色顺序、状态维度和动作尺度需要随 checkpoint 一起归档，保证推理输入输出具有统一物理含义。

06 · 数据边界

教师强制与闭环误差

教师强制展示局部预测质量；固定 seed 闭环配合 action trace，能够定位接近、接触、抓取、抬升或释放阶段的累计误差。

07 · 资产授权

官方资产与任务分布

官方 BlenderKit 或专属资产需要独立归档和授权记录，确保任务场景、论文配置与评估分母保持同源。

08 · 评估拓扑

可重复的进程与随机性

冷启动、热复用、并行 worker、随机数初始化和视频保存路径都会影响结果。固定单进程拓扑和 seed，才能稳定比较 checkpoint。

09 · 远端存储

PVC 与远端工作流

PVC 保存数据，训练脚本、环境记录、checkpoint 同步和重连说明则构成云端重启后的恢复入口。

08 / REPRODUCTION

学习者如何从零复现

从最小闭环开始，再扩展到长训和正式评估。下面的命令使用占位变量，便于学习者把同一流程迁移到本地 AMD GPU、PVC 工作区或新的项目仓库；具体脚本、Notebook 和公开权重构成统一入口。

export DATA_ROOT=/path/to/data

# 2. Run an official reset/render check and save an MP4

# 4. Only then run the fixed task/seed evaluation

  --checkpoint /path/to/checkpoint \\
  --seeds 0 1 2 3 4 \\

09 / PUBLICATION

公开什么，保留什么

  • 公开层：迁移门禁、问题分类、修复原则、结果 JSON、代表视频、公开权重链接、上游仓库。
  • 私有层：token、SSH 私钥、云端端点、个人绝对路径、私有资产和未经授权的 BlenderKit 内容。
  • 结果标签：诊断回放、展示视频、专家回放和正式成功率按用途清晰标注。
  • 复核入口：每个正式结果绑定任务集合、seed、分母、JSON、视频和 SHA256。
